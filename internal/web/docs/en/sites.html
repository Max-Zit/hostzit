Websites, PHP and page cache

A website is a domain (with www and more aliases) served from a folder of the account, by default ~/sites/DOMAIN/public.

New website

Enter the domain under Websites → New website. HostZit creates the folder with a first page, the web server configuration and, when you ask for it, the DNS zone. Point the domain to the server (or set the name servers at the registrar); a free Let's Encrypt certificate follows automatically and is renewed 30 days before it expires.

Settings

  • PHP version per website.
  • Main address: with or without www; the other one redirects.
  • Redirect HTTP to HTTPS and HSTS.
  • Redirects: one per line, e.g. /old /new 301.
  • Aliases: more domains that show the same website.
  • Own certificate: paste a certificate and its key instead of Let's Encrypt.

Page cache

With the page cache on, the web server keeps finished pages and answers visitors without starting PHP: pages come much faster and the server has far less work. Logged-in users, the WordPress admin, comment authors, shopping carts, forms (POST) and addresses with a query always get fresh pages. Pages are kept for the time you choose; Clear cache removes everything at once (use it after changes to the design or content). The response header X-Cache shows HIT, MISS or BYPASS.

Access and protection

  • Web application firewall (ModSecurity with the OWASP Core Rule Set, tuned for WordPress) blocks SQL injection, cross-site scripting and scanners.
  • Only these addresses / Blocked addresses: IP rules for the whole website.
  • Hotlink protection: other websites cannot embed your images and videos.
  • Folders with a password: visitors of a folder must enter a user name and password.

Logs

Logs shows the last visits and errors of the website; PHP errors are in ~/logs/php-error.log.
