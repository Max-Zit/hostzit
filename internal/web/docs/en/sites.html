Websites, PHP and page cache

A website is a domain (with www and more aliases) served from a folder of the account, by default ~/sites/DOMAIN/public.

New website

Enter the domain under Websites → New website. HostZit creates the folder with a first page, the web server configuration and, when you ask for it, the DNS zone. Point the domain to the server (or set the name servers at the registrar); a free Let's Encrypt certificate follows automatically and is renewed 30 days before it expires.

Settings

  • PHP version per website.
  • Main address: with or without www; the other one redirects.
  • Redirect HTTP to HTTPS and HSTS.
  • Redirects: one per line, e.g. /old /new 301.
  • Aliases: more domains that show the same website.
  • Request the certificate again / Renew now: asks Let's Encrypt right away, for example after the DNS was fixed (at most once per 15 minutes per website; Let's Encrypt blocks a name after a few failed tries an hour). Otherwise a failed request is retried every few hours and certificates renew 30 days before they expire.
  • Own certificate: paste a certificate and its key instead of Let's Encrypt.
  • Access by country: refuse visitors from chosen countries or continents, or allow only them (they get 403). Hold Ctrl (or ⌘) to choose several; the search field finds a country. Needs the country database on the server (the administrator downloads it once).

Page cache

With the page cache on, the web server keeps finished pages and answers visitors without starting PHP: pages come much faster and the server has far less work. Logged-in users, the WordPress admin, comment authors, shopping carts, forms (POST) and addresses with a query always get fresh pages. Pages are kept for the time you choose; Clear cache removes everything at once (use it after changes to the design or content). The response header X-Cache shows HIT, MISS or BYPASS.

Access and protection

  • Web application firewall (ModSecurity with the OWASP Core Rule Set, tuned for WordPress) blocks SQL injection, cross-site scripting and scanners. Only log notes what it would block without blocking (to test first). Firewall: latest requests lists blocked requests with the rules that matched; Rule … off switches a rule off for this website when a legitimate request was blocked. The administrator installs the firewall once under Settings → Sign-in and security.
  • Only these addresses / Blocked addresses: IP rules for the whole website.
  • Hotlink protection: other websites cannot embed your images and videos.
  • Folders with a password: visitors of a folder must enter a user name and password.

Visitor statistics

Visitors on the website's page counts the web server's logs of the last month with GoAccess: visitors and requests per day, data sent, the most visited pages, where visitors come from, pages not found, browsers and operating systems. Visitors are counted once a day by address and browser; addresses are not shown. The report is kept for an hour; Update counts again.

Redis object cache

When the package includes Redis memory, PHP → Redis object cache starts an own Redis for the account, reachable only by the account through the socket /.sock/redis.sock (no network port). WordPress → the site → Connect to Redis installs and sets up the plugin Redis Object Cache; the panel shows memory, keys and hits, Empty the cache clears it.

Git deployment

Under Git a repository in ~/repos/NAME.git is deployed into a folder of a website: the chosen branch is checked out there, then an executable file .hostzit-deploy from the repository runs in that folder (composer install, npm run build …; up to 10 minutes). Deploy in one of two ways:

  • Push over SSH (packages with SSH): git remote add hosting ssh://USER@SERVER/home/USER/repos/NAME.git, then git push hosting main; the output of the deployment comes back with the push.
  • Clone from an https:// address (GitHub, GitLab, Gitea …; for a private repository with a read-only token in the address): Pull and deploy in the panel, or the webhook address entered in the repository's settings deploys on every push.

The output of the last deployment and the latest commits are on the repository's page. Files that are not in the repository stay in the folder.

Node.js and Python applications

Under Applications a Node.js or Python program runs permanently as the account (restarted when it stops, within the package's limits). It listens on a socket whose address is in the variable PORT — Node.js: app.listen(process.env.PORT); Python: gunicorn --bind unix:$PORT app:app. Network ports cannot be opened. Enter the folder, the start command and environment variables; Run a command installs packages (npm ci, python3 -m venv .venv, .venv/bin/pip install -r requirements.txt). Serve with this application sends a website to it: files that exist in the website's folder are still served directly, everything else (WebSockets too) goes to the application. The page shows the state, restarts and the application's output.

Logs

Logs shows the last visits and errors of the website; PHP errors are in ~/logs/php-error.log.
