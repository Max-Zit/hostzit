Users, settings and updates

Administrators

Under Administrators: administrators do everything, operators manage customers, websites and DNS, viewers only look (support). Every administrator signs in with two-factor sign-in; add an e-mail address for company sign-in and notices.

Settings

  • Hosting: shared or dedicated, server name, IP addresses, name servers, secondary name servers, default PHP, Let's Encrypt, grace period of terminated customers.
  • Network and access: ports and allowed networks of both panels.
  • Sign-in and security: session length, sign-in blocks, two-factor sign-in for customers, four-eyes approval, addresses blocked for the whole server.
  • Company sign-in: OpenID Connect for administrators.
  • Updates: check and install signed new versions; release channel official or testing.
  • Panel backup: nightly encrypted backups of the panel database and keys.
  • EmailZit: link to the mail hosting.
  • Notifications: SMTP server for notices and for mail from websites.

Certificate of the panels

With Let's Encrypt switched on under Settings → Hosting, the panels get a certificate for the server name and the host of the customer panel address, as soon as these names point to the server; it is renewed 30 days before it expires. Until then, and when the panel is opened by IP address, it uses its own self-signed certificate.

PHP versions

Settings → PHP installs further PHP versions (5.6 to 8.6) from packages.sury.org, the repository of Debian's PHP maintainer, with the usual extensions, and removes versions no website uses. Each website chooses its version; packages that list PHP versions need a new version added.

Clicking a version opens its extension list (like EasyApache): checked extensions are installed from the Debian packages, unchecked ones are removed, and all accounts get the change within a minute. fpm, cli, common, opcache and readline always stay. Each customer can switch installed extensions off for their own websites and set php.ini values such as memory_limit, upload_max_filesize, max_execution_time or date.timezone under PHP in the customer panel; memory and upload size stay within the package limits.

System updates

Settings → System lists the Debian and PHP packages that wait (security updates are marked). Check now reads the package lists anew; Install now installs everything in the background (log under Last installation). The nightly security updates install the Debian security updates and the PHP versions from packages.sury.org each night with unattended-upgrades. After every package change the PHP processes of accounts that still run a replaced PHP restart by themselves, so a patched PHP is really in use. The server is never restarted by itself: when a new kernel needs it, the page says so.

Remote backups

Settings → Remote backups uploads every active account (files, databases, settings) each night to an SFTP server or an S3 bucket (Amazon, MinIO, Wasabi, Backblaze B2 …) and keeps the newest copies per account. For SFTP add the shown key to ~/.ssh/authorized_keys on the backup server, or enter a password; the server's host key is remembered at the first connection. Test the connection writes and deletes a test file. To restore, open Remote backups on the customer's page, choose a copy and then restore it under Import.

Updates

Releases are signed by MaxZit. The server installs a release only if its signature and checksum match; the panel database is saved first. Websites keep running during an update.

Restore the panel

On a new server: install HostZit, stop hostzit-server, run hostzit-server --restore FILE.hzb (the passphrase is asked), start the service, then use Set up again for each customer. The customers' files and databases come from their own backups.

Command line

hostzit-server --unblock-ip ADDRESS|all     lift a sign-in block
hostzit-server --reset-allowlist             allow the admin panel from private networks again
/usr/lib/hostzit/hostzit-helper ops          list the helper's operations
hostzit-server --test-no-2fa                 test servers only: sign-in without the second factor (warning on every page)
