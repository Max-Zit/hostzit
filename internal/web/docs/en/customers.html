Customers and packages

A package is a plan with limits; a customer is a hosting account on a package. Each customer is its own Linux user, so its websites, files and processes are separate from all others.

Packages

  • Disk space and files are enforced by disk quotas.
  • CPU (100 % = one core), memory, processes, disk priority and disk speed (MB/s for reading and writing each) apply to everything the account runs: PHP, cron jobs, SSH, applications and tools.
  • Redis memory: the customer may switch on an own Redis object cache of this size (0 = none).
  • Node.js and Python applications: how many applications the customer may run (0 = none).
  • PHP workers limit how many requests PHP handles at the same time; memory per request and largest upload go into PHP's settings.
  • Mails per hour limits mail from the websites.
  • SSH gives shell access; without it the customer has SFTP only.

Changing a package applies the new limits to all its customers at once.

Customers

  • Account name: 3–16 lowercase letters and digits. It is the Linux user, the SFTP login and the prefix of the databases (shop_wp).
  • Suspend: websites show a "temporarily unavailable" page, PHP and the customer's sign-in stop. Unsuspend brings everything back.
  • Terminate: like suspend; the files are deleted after the grace period (Settings → Hosting).
  • Open the customer panel signs you in as the customer with a banner; everything you do is recorded with your name.
  • Set up again writes the account's system configuration again (after a restore or a manual change).

Resource usage

Resource usage lists every account with its CPU, memory, disk speed and processes of the last 10 minutes, the average and peak CPU of the last day and its limit hits: 10-minute intervals in which the CPU limit slowed the account down (by a quarter of the time or more) or the memory limit ended processes. Sort by any column. Customers see their own hits under Usage → Limits reached; an account held back for an hour or more in a day gets a notification.

Import

Copy full cPanel backups (cpmove-USER.tar.gz) to /var/lib/hostzit/import and start the import under Import. HostZit creates the account and moves the websites (main, addon, sub and parked domains), databases with their users and passwords, DNS zones (with the new server address) and cron jobs. Keep the same account name so the websites' database settings stay valid. The rest of the old home folder is in ~/cpanel-home.

HostZit archives (the customers' own backups, remote backups fetched back, accounts of another HostZit server) are restored the same way: the account comes back with its websites, DNS zones, databases with their users and passwords, cron jobs, PHP settings, Redis, applications and Git repositories. Leave the account name empty to keep the archive's name.

Move to another server

On the customer's page, Move to another server sends the account to another HostZit server (like WHM's Transfer Tool). On the target, create an API token (My account → API tokens) with customers:read and customers:write; enter the target's admin panel address (https://host:8442) and the token and click Check the target. The target needs a package with the same short name as the account.s package here; the check says so before anything is sent, and also when the target already has an account with that name. HostZit shows the target's version and the SHA-256 fingerprint of its certificate: when the target uses its own (self-signed) certificate, compare it with openssl x509 -in /var/lib/hostzit/panel/tls/panel.crt -noout -fingerprint -sha256 on the target. The move packs the account and streams it to the target, which creates it with the same name, panel password and database passwords; the result is under Jobs. When asked, the account is suspended here afterwards. The websites keep running on the old server until the domains point to the new one (change the DNS records or the name servers); Git webhook addresses change, and the customer sets up two-factor sign-in again.

Four-eyes approval

With four-eyes approval on (Settings → Sign-in and security), deleting or terminating a customer and deleting a package wait under Approvals until a second administrator approves them.
