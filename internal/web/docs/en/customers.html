Customers and packages

A package is a plan with limits; a customer is a hosting account on a package. Each customer is its own Linux user, so its websites, files and processes are separate from all others.

Packages

  • Disk space and files are enforced by disk quotas.
  • CPU (100 % = one core), memory, processes and disk priority apply to everything the account runs: PHP, cron jobs, SSH and tools.
  • PHP workers limit how many requests PHP handles at the same time; memory per request and largest upload go into PHP's settings.
  • Mails per hour limits mail from the websites.
  • SSH gives shell access; without it the customer has SFTP only.

Changing a package applies the new limits to all its customers at once.

Customers

  • Account name: 3–16 lowercase letters and digits. It is the Linux user, the SFTP login and the prefix of the databases (shop_wp).
  • Suspend: websites show a "temporarily unavailable" page, PHP and the customer's sign-in stop. Unsuspend brings everything back.
  • Terminate: like suspend; the files are deleted after the grace period (Settings → Hosting).
  • Open the customer panel signs you in as the customer with a banner; everything you do is recorded with your name.
  • Set up again writes the account's system configuration again (after a restore or a manual change).

cPanel import

Copy full cPanel backups (cpmove-USER.tar.gz) to /var/lib/hostzit/import and start the import under Import. HostZit creates the account and moves the websites (main, addon, sub and parked domains), databases with their users and passwords, DNS zones (with the new server address) and cron jobs. Keep the same account name so the websites' database settings stay valid. The rest of the old home folder is in ~/cpanel-home.

Four-eyes approval

With four-eyes approval on (Settings → Sign-in and security), deleting or terminating a customer and deleting a package wait under Approvals until a second administrator approves them.
