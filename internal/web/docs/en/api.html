REST API for billing

Your billing system or portal creates, suspends and terminates accounts, changes packages and opens the customer panel through the API of the admin panel (port 8442).

Tokens

Create a token under My account → API tokens and choose what it may do: customers:read, customers:write, usage:read, sso:create, dns:mail (EmailZit). Send it as Authorization: Bearer hzt_….

Conventions

  • JSON, times in RFC 3339 UTC; lists with ?limit= and ?cursor=, answer {"items": […], "next_cursor": "…"}.
  • Errors: {"error": {"code": "invalid", "message": "…", "field": "domain"}}.
  • Idempotency-Key on POST: a repeated request returns the first answer (24 hours).
  • Slow work answers 202 with a job_id; follow it at GET /api/v1/jobs/{id}.
  • {id} is the customer UUID, ext: + your own id, or the account name.

Endpoints

GET    /api/v1/packages
GET    /api/v1/customers
POST   /api/v1/customers                {"id","external_id","username","package","name","email","password","domain","dns"}
GET    /api/v1/customers/{id}
PATCH  /api/v1/customers/{id}           {"name","email","password"}
PUT    /api/v1/customers/{id}/package   {"package": "wp-pro"}
POST   /api/v1/customers/{id}/suspend   {"reason": "billing"}
POST   /api/v1/customers/{id}/unsuspend
POST   /api/v1/customers/{id}/terminate
GET    /api/v1/customers/{id}/usage
POST   /api/v1/customers/{id}/sso       → {"url": "…"} one-time sign-in link, 60 s
POST   /api/v1/customers/{id}/export    → job: account backup in ~/backups
GET    /api/v1/customers/{id}/backups
GET    /api/v1/jobs/{id}
GET    /api/v1/server/status
