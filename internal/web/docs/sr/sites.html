Sajtovi, PHP i keš stranica

Sajt je domen (sa www i drugim aliasima) koji se služi iz foldera naloga, podrazumevano ~/sites/DOMEN/public.

Nov sajt

Unesite domen u Sajtovi → Nov sajt. HostZit pravi folder sa prvom stranicom, konfiguraciju web servera i, ako želite, DNS zonu. Usmerite domen na server (ili postavite name servere kod registra); besplatan Let's Encrypt sertifikat stiže sam i obnavlja se 30 dana pre isteka.

Podešavanja

  • Verzija PHP-a po sajtu.
  • Glavna adresa: sa ili bez www; druga se preusmerava.
  • Preusmeri HTTP na HTTPS i HSTS.
  • Preusmeravanja: jedno po redu, npr. /staro /novo 301.
  • Aliasi: drugi domeni koji prikazuju isti sajt.
  • Zatraži sertifikat ponovo / Obnovi sada: odmah pita Let's Encrypt, npr. posle ispravke DNS-a (najviše jednom u 15 minuta po sajtu; Let's Encrypt blokira ime posle nekoliko neuspelih pokušaja na sat). Inače se neuspeo zahtev ponavlja na svakih nekoliko sati, a sertifikati se obnavljaju 30 dana pre isteka.
  • Sopstveni sertifikat: nalepite sertifikat i ključ umesto Let's Encrypt-a.
  • Pristup po zemlji: odbijte posetioce iz izabranih zemalja ili kontinenata, ili dozvolite samo njih (dobijaju 403). Štiklirajte zemlje ili cele kontinente; polje za pretragu nalazi zemlju, a izabrane se pre čuvanja prikazuju kao odbijene ili dozvoljene. Potrebna je baza zemalja na serveru (administrator je jednom preuzme).

Keš stranica

Kada je keš stranica uključen, web server čuva gotove stranice i odgovara posetiocima bez pokretanja PHP-a: stranice su mnogo brže, a server ima daleko manje posla. Prijavljeni korisnici, WordPress admin, autori komentara, korpe, forme (POST) i adrese sa upitom uvek dobijaju sveže stranice. Stranice se čuvaju koliko izaberete; Očisti keš briše sve odjednom (posle izmene dizajna ili sadržaja). Zaglavlje odgovora X-Cache pokazuje HIT, MISS ili BYPASS.

Pristup i zaštita

  • Web aplikacioni firewall (ModSecurity sa OWASP Core Rule Set-om, podešen za WordPress) blokira SQL injection, cross-site scripting i skenere. Samo loguj zapisuje šta bi blokirao, bez blokiranja (za probu). Firewall: najnoviji zahtevi prikazuje blokirane zahteve sa pravilima koja su okinula; Pravilo … isključeno isključuje pravilo za ovaj sajt kada je blokiran ispravan zahtev. Administrator instalira firewall jednom pod Podešavanja → Prijava i bezbednost.
  • Samo ove adrese / Blokirane adrese: IP pravila za ceo sajt.
  • Zaštita od hotlinkovanja: drugi sajtovi ne mogu da ugrađuju vaše slike i video.
  • Folderi pod lozinkom: posetioci foldera moraju da unesu korisničko ime i lozinku.

Statistika posetilaca

Posetioci na stranici sajta broje logove web servera za poslednji mesec pomoću GoAccess-a: posetioce i zahteve po danu, poslate podatke, najposećenije stranice, odakle posetioci dolaze, nepostojeće stranice, pregledače i operativne sisteme. Posetilac se broji jednom dnevno po adresi i pregledaču; adrese se ne prikazuju. Izveštaj se čuva sat vremena; Ažuriraj broji ponovo.

Redis keš objekata

Kada paket uključuje Redis memoriju, PHP → Redis keš objekata pokreće sopstveni Redis naloga, dostupan samo tom nalogu preko socketa /.sock/redis.sock (bez mrežnog porta). WordPress → sajt → Poveži sa Redis-om instalira i podešava plugin Redis Object Cache; panel prikazuje memoriju, ključeve i pogotke, a Isprazni keš ga briše.

Git deploy

Pod Git se repozitorijum u ~/repos/IME.git postavlja u folder sajta: izabrana grana se tamo checkout-uje, a zatim se u tom folderu pokreće izvršni fajl .hostzit-deploy iz repozitorijuma (composer install, npm run build …; najviše 10 minuta). Postavlja se na jedan od dva načina:

  • Push preko SSH-a (paketi sa SSH-om): git remote add hosting ssh://NALOG@SERVER/home/NALOG/repos/IME.git, pa git push hosting main; izlaz postavljanja stiže uz push.
  • Kloniranje sa https:// adrese (GitHub, GitLab, Gitea …; za privatni repozitorijum sa tokenom samo za čitanje u adresi): Povuci i postavi u panelu, ili webhook adresa uneta u podešavanja repozitorijuma postavlja posle svakog push-a.

Izlaz poslednjeg postavljanja i poslednji commit-ovi su na stranici repozitorijuma. Fajlovi koji nisu u repozitorijumu ostaju u folderu.

Node.js i Python aplikacije

Pod Aplikacije Node.js ili Python program radi stalno kao nalog (ponovo se pokreće kada stane, u granicama paketa). Sluša na socketu čija je adresa u promenljivoj PORT — Node.js: app.listen(process.env.PORT); Python: gunicorn --bind unix:$PORT app:app. Mrežni portovi ne mogu da se otvore. Unesite folder, komandu za pokretanje i promenljive okruženja; Pokreni komandu instalira pakete (npm ci, python3 -m venv .venv, .venv/bin/pip install -r requirements.txt). Opslužuj ovom aplikacijom šalje sajt aplikaciji: fajlovi koji postoje u folderu sajta i dalje se služe direktno, sve ostalo (i WebSockets) ide aplikaciji. Stranica prikazuje stanje, ponovna pokretanja i izlaz aplikacije.

Logovi

Logovi prikazuju poslednje posete i greške sajta; PHP greške su u ~/logs/php-error.log.
